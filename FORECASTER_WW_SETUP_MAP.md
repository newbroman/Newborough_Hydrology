# Newborough — WW + Forecaster: where things live & how to run it

*A map for the live‑data / Water Watch workstream.*

## The model (yours, confirmed)

**One folder on your machine = your NHGR clone.** Each month: `git pull` to bring
in the latest PL data, run the scripts locally, `git push` to send the WW +
forecaster files back. The private master ODS lives inside the clone but is
**never pushed** (a `.gitignore` rule keeps it out).

You already push PL changes to NHGR, so the git auth is set up — this rides on
the same routine.

## One‑time setup

1. **Working folder** = your existing NHGR clone.
2. **Add the `.gitignore` lines** so the private ODS never pushes (provided
   separately).
3. **Seed the hub once**, then commit it:
   ```
   python3 src/living/seed_living_hub.py \
       --maod outputs/01_wells_clean_maod.csv \
       --locations data/Well_locations_height.csv \
       --out data/living/readings_living.csv
   git add data/living/readings_living.csv && git commit -m "seed living hub" && git push
   ```

## Monthly routine

```
1.  git pull                                  # refresh PL data + other changes
2.  (intake)  readings → ODS  +  append hub   # intake_monthly.py  [append: pending]
3.  ./ww/run_report.sh                         # WW newsletter + difference maps
4.  python3 src/living/update_forecaster_feed.py \
        --hub data/living/readings_living.csv \
        --cluster-map outputs/03_master_data.csv \
        --out outputs/11b_spatial_thresholds/latest_readings.json
5.  python3 src/living/update_forecaster_msl5.py \
        --hub data/living/readings_living.csv \
        --cluster-map outputs/03_master_data.csv \
        --out outputs/11b_spatial_thresholds/forecaster_msl5.json
6.  git add data/living/readings_living.csv outputs/11b_spatial_thresholds/*.json
    git commit -m "monthly update YYYY-MM"
    git push
```

If you want the WW newsletter PDF published too, add it to the `git add` in
step 6 (e.g. into `docs/` or `ww/output/`).

## The git part, plainly

- `git pull` = pull the latest down. `git push` = send your changes up.
- `git add` + `git commit -m "…"` = pick the files to send and label the change.
- Nothing here re‑authenticates; it's the same push you already do for the PL.
